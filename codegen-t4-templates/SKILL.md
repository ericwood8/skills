# CodeGenNew templates

## 1. Reproducing existing code

1. Read **all** the hand-written examples and note what varies (hand-picked names, extra members, deliberate relaxations).
2. Read the live schema and data (read-only `sqlcmd`) for anything that becomes code (lookup rows become enum members).
3. Write the template so the output for the simplest example matches **exactly** (the diff may show only trailing whitespace, BOM, final newline). Project facts (namespaces, context type, enum tables, tables with no entity) are variables at the top of the template or project settings, never engine code.
4. Generate for **every** table into a scratch copy, compare with the originals (`git diff -w --ignore-cr-at-eol`). Overwrite only a close approximation; **revert the rest and list it as hand-maintained** with the reason.
5. Prove it: build the target. Generated code for tables with no screen or route is not type-checked unless referenced: route it in a scratch copy.
6. Fix a bug in the template so all tables get it, not only the sample.
7. **A generator that follows the column is stricter than hand code that relaxes it** (a nullable property over a NOT NULL column makes the API refuse requests that omit it). Treat "generated is stricter" as a reason to keep the file hand-maintained; "looser" is acceptable but must be reported.
8. A template header lists what a generator cannot know: collection navigation names, reverse navigations (both sides loop in JSON), enum-typed properties, validation attributes, hand-picked sort columns, detail grids and dependent drop-downs, registration lines.

## 2. T4 and escape traps

- Signal an error with `Error("...")` in a statement block and wrap **all output in the success branch**. A compile error comes back in `TemplateResult.Errors`: put `string.Join(" | ", result.Errors)` in test assertion messages. Usual causes: missing `<#@ import namespace="System.Data" #>` (for `SqlDbType`) or `System.Collections.Generic` (for `List<>`).
- Build output with a `StringBuilder` and `Append('\n')` (`Environment.NewLine` mixes CRLF into LF). Templates are LF in the repo, CRLF in a Windows checkout: normalise `\r\n` in test helpers. Generated files have no BOM.
- A template gets `Model` (`TableModel`) and `Project`; extra needs are `.tt.config` switches: `NeedsRowData`, `NeedsReferencedDisplayColumns`, `RequiresPrimaryKey`, `TableOnly`, `OutputName` (a pattern with `{Table}`).
- Templates are **embedded resources**: rebuild the CLI after editing; the exe is in `bin\Debug\net10.0\`, not an older `win-x64\` folder. The CLI seeds its `Templates` folder once and never overwrites it: **delete `bin\Debug\net10.0\Templates` before a run** or old templates run and look like a template bug.
- **Never write `--` in template text** (illegal in a generated XML/XAML/HTML comment; a test scans `Templates\*.tt`). Use ` - `, a colon, `=====`. Legitimate: `<!--`/`-->`, an SQL comment at the start of a line in an `SP_` template, C# `i--`. For a CLI flag in generated text build it: `new string((char)45, 2) + "port"`; name a flag in words in a comment. Markdown table separator rows and Mermaid arrows need hyphens: `new string((char)45, n)`.
- `global::Ns.Type` inside `{ }` of an interpolated string reads `::` as a format specifier: use a variable.
- `ColumnModel.MaxLength` of an `nvarchar` is in **bytes**: halve it for characters.
- Reserved-word names come from the schema reader (`IsCSharpReservedWordName`); `Sample.Column` in tests sets it from the name.
- A word ending in `s` is not pluralised (`CustomerStatus` is `/api/customerstatus`): take plurals from `Pluralizer`, never guess them in a test.
- **Editing a template that writes C#/TypeScript strings with `\n`, quotes or backslashes:** use the Edit tool, or a script file made with the Write tool that does exact-string replace and **throws unless the match count is exactly 1** (Node: `s.replace(a, () => b)` so `$` is not interpreted). A `\n` meant for the generated file written through a Python or shell string became a real line break (CS1010 "Newline in constant"). `grep` the changed line afterwards. See the git-bash-editing skill. Test helpers that render a template should build keys with `FromValues`, not strings with line breaks.
- To emit lines from a T4 helper: `void Emit(List<string> lines)` calling `Write(line)` and `Write(((char)10).ToString())`.
- To see what the schema reader decided, write a throwaway console project referencing Core, Connections and SchemaIntrospection and print the model's flags; a diagnostic `.tt` through the CLI gives only a stack trace.

## 3. Multi-file output and generated names

- Several files (an Angular component's css/html/spec/ts) or subfolders: emit `@@@FILE Models/Customer.cs@@@` before each file (`GeneratedFiles` splits; relative paths, no `..`, no drive; a marker followed directly by another gives an empty file). Point `-o` at the project root (Angular: `src\app`). Write only when text differs after normalising `\r\n`.
- API route: strip `E_` then `SY_`, lower-case, add `s` (`E_DonateLeave` is `/donateleaves`); the Angular dev proxy strips `/api`. The generator and every hand-written base must use the same `Pluralizer`.
- JSON names follow ASP.NET camel-casing (`FixCasing`): lower-case the first char and keep lower-casing while the next char is upper, stopping at the first char followed by a non-upper (`IsActive` is `isActive`, `SY_IsoCountry_Alpha3Code` is `sY_IsoCountry_Alpha3Code`, `E_TimeSheetId` is `e_TimeSheetId`). A TypeScript interface with the wrong case reads `undefined` silently.
- Navigation property: the FK column without its trailing `Id` (`DonateFrom_EmployeeId` becomes `DonateFrom_Employee`); skip it if it collides with a column.
- A naming rule that changes names changes the JSON the shared front ends read (Pascal-casing `require_customer_po` gives `RequireCustomerPo`, SQL Server has `RequireCustomerPO`): keep an `Acronyms=PO,UPC,MSRP` project list taken from the other database's capital runs.
- `NamingStyle=Pascal` converts at the schema reader; SQL keeps the real names. **A C#/TypeScript identifier uses `Name`; anything inside SQL text or `[Table]`/`[Column]` uses `DbName`** (`ColumnModel.DbName`, `TableModel.DbTableName`, `ForeignKeyModel.ReferencedDbTable/Columns/DisplayDbColumns`). EF allows one `[Column]` per property: one attribute carries real name and type. A PostgreSQL branch that wrote `Model.TableName` into SQL breaks for `snake_case` read with `NamingStyle=Pascal`.

## 4. Where rules live

- **Rules that must be the same on every platform belong in `CodeGenNew.Core`**, called by every stack's template, with a unit test: `FormPages.For`, `GridColumns.ForGrid`, `GridCaption.For`, `NumericClassifier.DecimalRange`, `DisplayColumnSelector`, `ColumnTypes` (type maps for every language, with a data-row test over every `SqlDbType`), `Labels.Words`, `JsonNames.Camel`, `ColumnRules`/`ColumnModel.RuleOf(project)` (validators in CS, zod and Angular all read it), `CloneShape`, `SearchPlan`, `DialectInfo` (quoting, paging, placeholders), `EntityNavigations`, `BlazorNames`, `ScreenNames`, `AngularVersions` (per-version Angular packages, builders, runner), `TableModel.HasCrudApi` / `HasSearchApi` / `HasNameActiveApi`. A template renders; it does not decide. Moving a copy out of a template is safe when every sample dry-runs unchanged.
- The rules for **which tables are listed** by a database-level template live in `DatabaseModel` and equal the per-table templates' rules, or a registration lists a table whose API was never written.
- Two templates that must agree on a name (a child link route and the menu route) share one Core rule plus a test that renders both and compares. A file written by two templates (`PaginationBar.xaml`) gets a test that cuts it out of both and compares.
- Anything a template needs about a **child** table is in `ChildForeignKeyModel.ReferencingTableColumns`; use it instead of guessing from names.
- A condition shared by a client call and a server route (`findByName` and `GET <route>/{name}`: NOT NULL text `Name`) is written in the same words in `API_Crud`, `TS_Service`, `TSX_Api`, with a test of the pair. `/{id:int}` beats `/{name}`; a literal `/search` or `/lookup` beats both.
- Split features that were bundled by accident (search bar and pagination): add the second flag, derive the first from only what it depends on, **delete the old single-flag branches** (no dead code), and thread the change through every layer (stored procedure, API endpoint, repository, each UI stack).
- Warn, do not fail, for a soft consistency problem (a child table with no screen): a comment in the generated file. `Error()` is for input that cannot produce a correct file. In a plan `Error()` fails the run: for a table with nothing to say write an empty result (refusals belong in the `.tt.config`).

## 5. Essentials and short generated classes on a base

- Move what every table repeats into a base written **once** by an essentials group; the per-table template writes only the table's facts (`CustomerApi : CrudApi<Customer, CustomerRepo>`, `HolidayService extends NamedCrudService<Holiday>`, screens `extends PagedCrudScreen<T>`). A behavior fix is one edit in the base.
- **Essentials are written once and kept** (`--replace` refreshes). A template that needs a base must say so in its header; a sample's `Regenerate.sh` runs `codegen essentials --stack api --groups crudapi` (and `--stack angular --groups crud`) before `generate`. **Never change what an essentials file must contain to make a page template work** (older projects keep the old file): put new UI in the page template. `-o` of `essentials` is the project root; the stack's `Output<Stack>` folder is appended.
- Keep the typed wrapper callers use (`getPage(...)` as a one-line call to `searchPage`) so no caller changes. A master-detail screen overrides `add()`/`edit()` and calls `super`.
- A group is `EssentialsGroup=` in the `.tt.config`; a whole-project plan includes a `NoDatabase=true` template only if it has one. Compare essentials output with a working sample's hand-written files (normalise line endings) before trusting it. An essentials `BaseApi` must compile alone and agree with the TypeScript routes (use `EndsWith(.., StringComparison.OrdinalIgnoreCase)`, strip `E_`/`SY_`); find such problems with a scratch `--essentials --build` into an empty folder, since samples already hold the hand-written helper.
- After such a change the test assertions on the old long output are the work: assert the short class and add tests of the base (`CrudScreenTests.Essential()`, `CrudApiTests.Essential()`; `GeneratedFiles` needs `using CodeGenNew.TemplateEngine;`).
- A generated screen's drop-downs read `getLookup()` (`GET <route>/lookup` answers `{ id, name, isActive }`) for a parent with a whole-number key; the lookup lists every row with its flag so inactive parents keep their name.
- Name/active tables (NOT NULL `Name` and `IsActive`) use `NameActiveRepo`, `NameActiveCrudApi`, `NameActiveCrudService`, `NameActiveCrudScreen` (no search endpoint, no paging); only the API and Angular handle them (`PlanTables=AspNetApi`). A table in `NoApiTables` gets no API (a user table with password hashes).
- Generated specs of the bases and screens may use only `describe`, `it`, `expect`, `beforeEach` (Angular 18 to 20 run Karma and Jasmine, 21 and 22 Vitest). Per-version package ranges, builders, runner, `outputPath`/`index`, `module` setting and `provideBrowserGlobalErrorListeners` live in `AngularVersions`: add a row, never a version test in a template. Check a version with `Docs/Verification/Test-AngularVersion.ps1`.

## 6. Plan, shapes and adding things

**Template shapes:** per table (`Model`, default; `RequiresPrimaryKey`, `TableOnly`, `OutputName`); `DatabaseOnly=true` (`Database`, one file for the whole database, an `@@@FILE` marker; the test that renders every shipped template feeds it a `DatabaseModel`); `NoDatabase=true` (only `Project`; run by hand or an essentials group); `InPlan=false` + the project's `PlanAlso` (opt-in); `Dialects=` (skipped quietly for another database); `AccessMode=Routines|Ef`. `SqlServerOnly=true` is forbidden by a test: use `Dialects=` and, for a per-table template run by hand, an `Error(...)` on `Model.Dialect`. Shared front-end support code (grid sort helpers) is a database-level template with literal text after an `@@@FILE` marker, not a hand-copied file.

**Whole-project plan keys:** `Stacks=`, `PlanTables=` (Entity, Context, Api, AspNetApi, Search, Screen, ScreenForm, ScreenDetailMaster, Junction, Enum, Audit, Temporal), `OutputRoot=`, `OutputFolder[.<Stack>]=`, `InPlan=false`, `Dialects=`. A template without them is silently left out. Compile each template once per run (`TemplateCache`); re-set session values and clear `Errors` between runs.

**Adding a template:**
1. `Templates/<Group>_<Name>_v1.tt` + `.tt.config`; the prefix picks the menu and default extension; a **new prefix** needs `TemplateInfo.ExtensionByGroup`.
2. `DefaultAssetSeeder.DefaultTemplateFileNames` (both files), or it is not shipped.
3. Group counts in `TemplateEngineTests.The_shipped_templates_are_all_offered_with_their_groups`.
4. `Docs/TemplateNotes/<Name>_v1.md`, the README row and count, a settings hint and key for any new setting.
5. A rendering test, and for generated **code** a real compile (several tables of a sample into a scratch project with a small round trip); for SQL apply it to a scratch database copy.

**Adding a project setting:** the `Keys` list, a one-line hint in `ProjectSettingsHints` (effect and what blank means; do not start with the value to type), a row in `Docs/Reference.md`, a tab in `ProjectSettingGroups` (at most 20 per tab, every key on exactly one tab), the control (`BooleanKeys`, `ProjectSettingChoices`, its `Numbers` table with min 1; a radio has at most 3 choices). A flag that adds templates (`ImpliedPlanTemplates`) says in its hint that the project must be regenerated and which stacks it needs. Optional features default off. When removing a setting remove it from all of those places plus the template header, notes, README and specs.

**Adding a stack:** `ProjectPlan.KnownStacks`, `ProjectSettingChoices.Stacks`, keys `Output<Stack>`/`Build<Stack>`/`Test<Stack>` (and `OutputFolderOf`), hints, tabs, `Reference.md` rows, `EssentialsCatalog.Stacks` and the Essentials menu item, `ProjectBuilder.DefaultCommand`, `ExtensionByGroup`, `DefaultAssetSeeder`, the group count, the CLI/settings text, and the front end's origin in `API_EssentialProgram`'s CORS list. Which tables get a file is one Core rule used by per-table and database-level templates. Razor: `@page` is a directive (a field named `page` fails RZ2005), `Name@Arrow(x)` reads as an e-mail address, a C# string inside an attribute needs single quotes, `▲` in a C# string needs `\u25B2`; build lines with an `L()` helper and replace tokens (`§T`) instead of nesting braces. Python stack: keep the same wire contract (routes, camelCase JSON, search answer, error shapes) so every front end runs unchanged; type map and names in Core (`PythonTable`, `PythonNames`); FastAPI answers 422 for a bad body, so register handlers writing ASP.NET-style problem JSON with 400; Pydantic writes `Decimal` as a string (`PlainSerializer(float, when_used="json")`); SQLAlchemy 2.0 style with `expire_on_commit=False`; never write the password (`PGPASSWORD`, `MYSQL_PWD`, `DB_PASSWORD`); byte-compile with `python -m compileall -q app` in a test (skip without Python); ask before installing a venv. A flag that implies a template changes the `ImpliedPlanTemplates` list: grep tests for the old list.

**Adding a database or access mode:** a `SqlDialect` and `DatabaseProvider` value, a connection factory in `CodeGenNew.Connections`, a `SchemaProviderBase` subclass (abstract members `ReadColumnsAsync`, `ReadForeignKeyRowsAsync`, `ReadRowCountAsync`, `ReadRowsAsync`, `ListTablesAsync`, `ListColumnSummariesAsync`; override `ReadIndexRowsAsync`, `ReadTableDescriptionAsync` when the catalog has them), `SchemaProviderFactory`, the CLI, the desktop dialog and menu dialect mapping, `EfProviderInfo`, essentials, `DialectInfo`. Map types onto the SQL Server vocabulary (`int`, `bit`, `datetime2`, `varchar(-1)`), keeping the real spelling in `SqlTypeDeclaration`. Check every `Dialect ==` ternary that falls back to SQL Server: a new dialect lands there. New schema input (indexes, comments): a `protected virtual` read in `SchemaProviderBase` (empty default), a catalog query in each provider, a live test that builds and drops a scratch table; comments are read from `sys.extended_properties` / `col_description` / `COLUMN_COMMENT`. Provider logic that is plain C# (`PostgresProcedures`, `MySqlProcedures`, `SearchCall`, literals) lives in Core and the `SP_*.tt` starts with `if (Model.Dialect == SqlDialect.X) { Write(...); return GenerationEnvironment.ToString(); }`. Put the provider choice in one generated `UseProvider(options, connectionString)` used by the web registration and a desktop `OnConfiguring`; the password is never in `appsettings.json` (Npgsql reads `PGPASSWORD`; the Oracle MySQL driver does not read `MYSQL_PWD`, so the method adds it). Declare the generated context `partial` (CsWinRT1028).

**A template that only fits some tables:** derive it from the table, not a setting. Put the shape rule in Core once (`AuditTableShape` used by `TableModel.IsAuditTable` and `AuditColumnClassifier`). A new "requires" key needs the property and parse in `TemplateConfig`, a reason in `TemplateConfig.Refuse`, a parameter on `TemplateInfo.AppliesTo`, the flag on `TableSummary` computed in **every** provider's bulk query, the call in `MainViewModel.GetApplicableTemplates`, and a `Reference.md` row. Keep it out of the default plan with `InPlan=false`. A template that writes a second table refuses clashes up front with a reason.

**Optional extras are switches:** a flag mapped by `ImpliedPlanTemplates` (`ApiDocs`, `ApiHttp`, `ApiFakers`, `ProjectDocs`, `ApiValidation`) or a branch in an essentials/template body, **off by default**, tested in both states.

## 7. SQL and dialect facts

- SQL Server `EXEC` of a procedure is not composable; PostgreSQL `RETURNS SETOF` functions are (`SELECT * FROM f(...)`) and a scalar needs `AS "Value"` for `SqlQueryRaw<int>`; Postgres wants parameters without a default first (call by name); `information_schema` booleans can be NULL (`COALESCE`); Npgsql maps `DateTime` to UTC-only `timestamptz` unless the column is `timestamp`. MySQL has no default parameters, no `CREATE OR REPLACE PROCEDURE` (`DROP ... IF EXISTS` + `DELIMITER $$`), no `RETURNING` (`LAST_INSERT_ID()`), treats a backslash in a string literal as an escape, stores table names lower case on Windows (`lower_case_table_names=1`), `ROW_COUNT()` is 0 when an update changes nothing, and Pomelo lagged EF Core (use Oracle's `MySql.EntityFrameworkCore`).
- **Sorting from user input without dynamic SQL:** compare the column name with a fixed list inside one `ORDER BY` of `CASE WHEN @SortColumn = N'Col' AND @SortDescending = 0 THEN col END ASC, CASE WHEN ... = 1 THEN col END DESC` per column and direction, then a fixed default order. Test with `x' OR 1=1 --`. A foreign key sorts by the parent's display column with a scalar subquery; alias the main table and qualify columns.
- **Adding parameters to a PostgreSQL function leaves the old one behind** ("function is not unique"): generate `DROP FUNCTION IF EXISTS "s"."f"(<old types>)` first. A MySQL signature change means regenerating the callers.
- **Calling a clone routine from EF:** SQL Server `OUTPUT` parameter with **named** arguments; PostgreSQL returns the key as the function value (`SqlQueryRaw<int>("SELECT ... AS \"Value\"")`, `=>` named notation); MySQL ends the procedure with `SELECT v_new_key AS \`Value\`` and the caller passes every argument in order. `SqlQueryRaw<T>` reads a scalar from a column called `Value`.
- A copy must not trip a unique column: give each unique text column a free value first (`SuggestUnique<Column>`, cut the source short so the suffix fits); offer clone only when all unique columns are text and the database assigns the key.
- **Apply the SQL after a signature change** (`APPLY_SQL=1`) and query the catalog (`sys.parameters`, `pg_proc`, `information_schema.PARAMETERS`) to confirm, or generated callers fail at run time with "too many arguments" while everything builds. Generated search procedures list columns, so re-create them after a column change.
- PostgreSQL enum columns: EF sends `text`; create an assignment cast (`CREATE CAST (text AS the_enum) WITH INOUT AS ASSIGNMENT`, also from `character varying`; `SP_EnumCasts` writes it). Cast to `::text` for `ILIKE`/ordering. A CHECK list is `= ANY ((ARRAY['A'::character varying, ...])::text[])`: parse only that shape; set `maxLength` to the longest value on an unbounded `text` column. A unique enum column cannot be cloned.
- A lookup table is not always an enum: a small `*Status` table is derived as an enum (no entity, repository, API); set `EnumTables=none` to show its description.
- **Test live with credentials from the environment:** unit tests cover type/default mapping, connection strings and procedure text; an integration test class runs only when `CODEGENNEW_<DB>_HOST/_DATABASE/_USER/_PASSWORD` are set (otherwise `Assert.Inconclusive`). Passwords go through `PGPASSWORD`/`MYSQL_PWD`, never into a repository file. The React and Angular front ends reuse any database's API unchanged (same routes and JSON): check a new database by starting its API on 5080/5081.
- **App shell (menu, routes): generate the list, keep the chrome.** Only the list of screens changes per table: generate it as its own file the hand-written shell imports (React `screens.tsx`, Angular `app.routes.ts`, a WinUI3 `partial class MainWindow` with `AddScreens()`/`ShowPage()`).
- A client-side sort of a grid that holds all its rows compares by value (numbers as numbers, dates as dates, text without case, nothing first), a column that shows a name sorts by the name, a WinUI3 row carries raw `Values`; key the stored sort `<grid>.<child>`.

## 8. Paging rules (every stack that has the screen)

- Limits in the endpoint: `Math.Clamp(pageSize, 1, 1000)` first (the answer carries the size used); pageNumber below 1 or an overflowing offset is a `Results.Problem` 400, never `BadRequest("text")`. `API_Crud` `GetAll` pages when `pageNumber`/`pageSize` is given and stays an array otherwise.
- Read the page again after a delete and **step back to the last page** when the page asked for is past the end (`if (items.length === 0 && totalCount > 0 && pageIndex > 0) { pageIndex = ceil(totalCount / pageSize) - 1; load(); return; }`); use the paginator's page size; say "Nothing found." only after the first response; generated specs test the first request and the step back.
- Fix it in Angular (`TS_Component`, `TS_DetailMasterComponent`), React (`TSX_Page`, `TSX_DetailMasterPage`), Blazor (`BLZ_Page`) and WinUI3 (`WinUI3_MasterScreen` + `PaginationBar`).
- Compare the generated version with the hand-built one on real data volume before porting; measure and remove machinery that shows no benefit.
- `ListProtocol=Search` changes only the Angular client (one search box, `?pageIndex&pageSize&sort=col:dir&search=`, answer `{ data, count }`); the generated API still answers the Columns protocol. `DefaultSorts` gives a paged screen its starting sort.

## 9. Generated documents and checks

- **OpenAPI:** read back with `Microsoft.OpenApi.Readers` (`diagnostic.Errors` empty, look at `Paths`/`Components.Schemas`), then probe the running API: every documented GET answers 200, `PUT /{id}` with a wrong body 400 (a missing route and a missing row are both 404), schema property names equal a real response's keys.
- **Mermaid:** `mermaid.parse(text)` under jsdom, plus a deliberately broken line so the check can fail. **Markdown tables:** escape a pipe in a cell.
- **FluentValidation and other libraries:** compile the generated classes in a scratch project with the real entities and the library (overload inference failed on `InclusiveBetween(0, 100)` for a `short?`). Other tools: `tsc --strict` over generated `.ts`, `Grpc.Tools` for `.proto`, the real database for SQL (SQL Server `BEGIN TRAN ... ROLLBACK`, PostgreSQL `CREATE DATABASE x TEMPLATE y`, MySQL apply and drop).
- A test column has to be one the screen shows (a text column of 100+ characters is multi-line and left out of grids); a column name with a quote breaks generated TypeScript and C#.
- Use `$(cygpath -u "$TEMP")` for Git Bash paths. Test helpers that render a template `Assert.Fail` with errors joined on one line (`ReplaceLineEndings(" ")`).
- The repository's leftover-names test fails a file that names the project or machine you tested on: say "a real server" in tests, docs and template comments.
- A probe that deletes can delete real data: check the target's children, probe a scratch copy, or capture and restore the row.

## 10. Regenerating and proving

- **One script per sample** (`docs\Regenerate.sh`): rebuild the CLI, delete the CLI's `Templates` folder, copy the project `.config` into the CLI's `Projects` folder, generate, print only `diff -rq --strip-trailing-cr` against a backup taken first, then build and test; a refusal is printed, not hidden. Samples: `C:\InvoiceSystem` (WinUI3, `APPLY_SQL=1` after a column change), `C:\InvoiceSystemReact`, `C:\InvoiceSystemAngular`, plus SQLite, PostgreSQL and MySQL ones. Order after a schema change: WinUI3 with `APPLY_SQL=1`, then React, then Angular. **Stop the sample's API first** (`MSB3021`), and do not re-run "just to be sure" while servers are up. Dry-run every sample after a Core or shared-template change: 0 created, 0 updated. New web sample: `ng new frontend --routing --style=css --ssr=false --zoneless=false --skip-git --ai-config=none --defaults --test-runner=vitest --skip-install`, add Material, CDK, animations, then the hand-written files in that sample's `Regeneration.md`.
- **Sync a template fix into an already-generated project:** fix the repo `Templates/<Name>.tt`, run `dotnet test`, rebuild the CLI (this refreshes its local copy and **wipes** project settings at the top of that copy), re-apply the project's settings there, regenerate, re-apply **hand-customizations** made to generated files, rebuild the target and confirm 0 errors.
- **A wrong test assertion:** copy the exact generated text from the failure's "Expected to find ... in:" block instead of re-deriving it; a `StringBuilder` template and a raw `<# #>` template format the "same" output differently. For a template whose render needs a child table, assert on the `.tt` source.
- **Prove with the real tools once per stack change**, in this order: template tests; `Regenerate.sh` of every sample that uses the changed templates (WinUI3 then `dotnet build -p:Platform=x64`); a scratch generation for a stack with no sample (`Stacks=Api,Blazor`, `--essentials --build`); run the generated API on a spare port (`--urls http://localhost:5090`, since `Urls` in `appsettings.json` wins) and `curl` edge cases (`pageSize=0`, `-3`, `100000`, `pageNumber=0`, `2000000000`, a list, a lookup, a search); drive pages in the browser pane and the WinUI3 app with UI Automation (winui3 skill); `ng build` and `ng test` for a version. For a new database or mode: a scratch database file, `codegen generate ... --essentials --build`, `Test-ApiCrud.ps1`, `Test-OpenApiRoutes.ps1` from the PowerShell tool. Unit tests of template text passed while a self-referencing foreign key, a child table referenced twice and the Angular 19 and 20 package files were still broken. Generated extras (fakers, validators, `.http`, Swagger) are best tested by building and using them; a scratch console project with a `ProjectReference` to the generated Web project can call generated classes.
