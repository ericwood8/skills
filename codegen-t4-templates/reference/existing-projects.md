# Regenerating an existing project and the first Generate All

Read this when: a project was generated earlier and fails to build after new templates, or the first Generate All against a real database misbehaves.

## Regenerating a project that already exists (essentials are kept, so refresh them)

- **After the templates change, the project's old essentials are wrong.** `generate --essentials` never overwrites, so a project generated earlier keeps its old `GenericRepo`, `Program.cs`, `.csproj`, `app.config.ts`, `package.json` and shell. Regenerating TimeEntry after the sign-in, text-key and toast features failed twice for exactly that: the old `GenericRepo<T>` could not take a text key (CS0305, CS0311), the kept `.csproj` lacked the JWT package (CS0234), and the kept `package.json` lacked `ngx-toastr` (the bundle failed on the import).
- **The fix lives in the project's `Regenerate.sh`, before `generate`:** `codegen essentials --stack api --groups crudapi,nameactive,jwt,program,baseclasses,baseapi --replace` and `--stack angular --groups crud,auth,docker,config,shell,build --replace`, then `npm install` in the front end. `--replace` is safe only when nobody edits those files by hand; say so in the project's `Regeneration.md`. `--list` shows the group names (`Jwt`, `Auth` and `Docker` are not ticked by default).
- **A setting that adds a feature adds files and edits others.** `ApiAuth=true` needs the `Jwt` group and a `Program.cs` that calls its setup; `Auth=true` needs the `Auth` group and `Config` (interceptor), `Shell` (user menu); `Toasts=ngx-toastr` needs `Config` and `Build`; `ListProtocol=Search` and `EditableChildren` need `crudapi` and `crud` with `--replace`. If a build error names a missing type or package after changing a setting, refresh the group that owns that file before suspecting a template.
- **Owned tables need their children checked.** `OwnedTables` scopes only the tables it names; a child table of an owned row (a time sheet's detail rows) has no owner column and stays open to every signed-in person. After enabling `ApiAuth`, list every table that has a foreign key to an owned table and look at its API for `Owner =>`.
- **Compare with the hand-written project using `compare_trees.py`** (C:\Github\tools) instead of a new script: `--a <generated> --dirs <api folder> --b <real> --bdirs <folders> --ext .cs --ignore-prefix E_`; a count of zero identical files is normal, the "only in" lists are the findings.
## Generate All against a real database: what the first run teaches

- **A fix that does not show up is usually a stale template.** `DefaultAssetSeeder` refreshes a `Templates` copy only when its hash is what it last wrote; otherwise it writes `<name>.new` beside it. Look in the app's `bin\...\Templates` (and the CLI's) for `*.new`, rename each over the original, rebuild, then regenerate. Say so to the user: it explains "still crashing after your fix".
- **Essentials files are refreshed only with Essentials plus Overwrite ticked** (`--essentials --replace`). A template that needs a new member in `ViewModelBase.cs` builds only after that; the generated app fails with CS0103 until then. Tell the user to tick both, and patch the generated copy by hand only to prove the build.
- **A column the generator cannot hold is a warning with a remedy, not a bug to hide:** a column named like its table (C# forbids a member named like its class), a `sql_variant` column, a lower-case name on WinUI3/Uno without `NamingStyle=Pascal`. All are fixed with `IgnoredColumns=Table.Column` (data is kept in the SQL scripts). Ask before making Generate All leave columns out by itself; the user may prefer to decide.
- **Foreign key to a non-primary-key column** (`Well.PrimaryExternStationID` to `Station.ExternStationID`): `HasPrincipalKey` makes the target column a required key, so any NULL there crashes every read of the parent table (SqlNullValueException). Such a key gets no navigation and no drop-down (`ForeignKeyModel.ReferencesPrimaryKey`).
- **Tables that cannot be enums or entities:** system tables of a sync framework (`scope_info`, `scope_templates`, `scope_parameters`, `*_tracking`) are excluded by `SystemTableFilter`; an empty table is not an enum (`RowCount > 0`); an enum table without a name column falls back to the first non-key string column.
- **One DbContext per desktop app means one gate:** every view model of a WinUI3/Uno app shares the single context, so loads take turns on one static `SemaphoreSlim` (`ViewModelBase.ContextGate`), not one per screen. A per-screen lock lets a second page start while the first still reads ("A second operation was started on this context instance").
- **Prove a generated model before the user runs the app:** `Docs/Verification/Tools/ef_read_all.py --app <Output\X.App>` reads every DbSet; and run the project's `sql` folder with `C:\Github\tools\run_sql_folder.py`. Both caught real defects here that a green build did not.
