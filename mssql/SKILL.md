# MS SQL Server

## Safety rules (apply whenever running SQL against SQL Server)

1. **Idempotent where possible.** No `CREATE TABLE IF NOT EXISTS`: guard DDL with `IF OBJECT_ID('dbo.TableName', 'U') IS NULL`. For seed data use `MERGE` or `IF NOT EXISTS (SELECT 1 FROM ... WHERE ...) INSERT ...`, not a plain `INSERT`.
2. **Single statement only.** Never send several statements separated by `;` (or on separate lines with no `GO`) in one execution: it protects against an accidental or injected stacked statement.
3. **Timeouts.** 10 s connection timeout (`Connection Timeout=10`). 30 s query timeout client-side (`SqlCommand.CommandTimeout = 30` / EF Core's command timeout): SQL Server has no server-side per-statement cap like MySQL's `MAX_EXECUTION_TIME`. `SET LOCK_TIMEOUT 30000;` bounds how long a statement waits on a blocked resource.
4. **Row cap.** Ad hoc inspection SELECTs use `SELECT TOP 10000 ...` (or `OFFSET 0 ROWS FETCH NEXT 10000 ROWS ONLY` with an `ORDER BY`).
5. **Credentials.** Never echo a full connection string or password; redact before showing any command or error output.

## Design and EF Core notes

- **Windows Integrated Auth does not work once the workload may run in a container or the cloud.** If that is possible, design for username/password auth from the start.
- The `mcr.microsoft.com/mssql/server` image is **Linux-based**. A locally tagged image is pushed under another name with a plain `docker tag mcr.microsoft.com/mssql/server:<version> <local-name>:local`; no rebuild.
- **Row count without a table scan:** query `sys.partitions` instead of `COUNT(*)`. Through EF Core use `SqlQueryRaw<int?>` and alias the column as `Value` so the scalar mapping picks it up.
- **EF Core provider swap in tests (SQL Server to InMemory):** `AddDbContext` registers its configuration as an additive `IDbContextOptionsConfiguration<T>`. Removing `DbContextOptions<TContext>` is not enough: remove **both** registrations or they collide.
- **Duplicate-row race under concurrent requests** (one row per natural key): pre-check for the duplicate **and** wrap the insert in `catch (DbUpdateException)`, re-querying in the catch body to confirm it was a duplicate (a catch filter cannot `await`); rethrow if it was not.
- `DATETIME2(0)` instead of `DATETIMEOFFSET` is reasonable when the application normalizes everything to UTC itself.
- **The same column twice in one `UPDATE ... SET` fails** (`Msg 264`: "specified more than once in the SET clause"); there is no "last write wins". When building `SET` fragments in code, guarantee at most one assignment per column: `IF <force-condition> SET col = <forced> ELSE IF <caller supplied a value> SET col = <caller's value>`, never two independent `IF`s that can both fire.

## Exporting data and schema

- `sqlcmd ... -E` can fail with "The -E and the -U/-P options are mutually exclusive" when `SQLCMDUSER`/`SQLCMDPASSWORD` are set in the environment (go-sqlcmd also trusts the Windows login by default): drop `-E`.
- **`sqlcmd` cuts long output lines** (variable-width columns default to 256 characters; `-y 0` is refused with `-h`; a concatenated `varchar(8000)` is not covered by `-y`). To export generated text use `bcp "SELECT ..." queryout file.txt -c -T -S server -d db -r '\n'`: no width limit; rows with embedded newlines span lines.
- To copy a schema to another database, dump `sys.tables/columns/types/default_constraints`, `sys.foreign_keys(+_columns)` and `sys.indexes(+_columns)` with `sqlcmd -W -h -1 -s "|"` into small files and generate the other DDL from them; generate `INSERT`s with a `SELECT` that builds the literals (`REPLACE(x, '''', '''''')`, `CONVERT(varchar(23), d, 121)`, `CASE bit WHEN 1 ...`) and run it through `bcp`.
- **Output for generated text:** `-y 0` (alone, never with `-h`) prints no header line; trim trailing spaces per line and add `-f 65001` for UTF-8. Prove a schema/seed script pair by creating an empty database, running both twice, regenerating the schema from the result and diffing it against the original.
- **Backup/restore for a scratch copy:** the service account writes the file, so use `SERVERPROPERTY('InstanceDefaultBackupPath')` and `RESTORE FILELISTONLY` to build the `MOVE` clauses. `sqlcmd -b` plus `$LASTEXITCODE` is how a PowerShell script learns of a failure.

## Scripts written from the catalog

- **CHECK constraints:** `sys.check_constraints` joined to `sys.columns` on `parent_object_id`/`parent_column_id`. A table-level check mentioning one column has `parent_column_id = 0`: find the column by reading the definition. `IN ('a','b')` is stored as an OR chain in the catalog's own order (`([s]='Closed' OR [s]='On hold' OR [s]='Open')`). Skip `is_disabled = 1`.
- **A key sequence table** (`GetNextID`) must lock the whole table (`WITH (TABLOCKX)`) inside its transaction, so every insert of every listed table queues behind one counter; say so next to the script. Seed each counter from `MAX(key)`.
- **Triggers that call a linked server run inside the writing statement:** an unreachable target (`Could not find server`) rolls back the user's write. `UPDATE(col)` is true when the column is in the SET list even if the value did not change. text, ntext and image columns cannot be read from `inserted`.
- A **bulk change across tables** needs no run-time metadata walk when the script is generated: write the plain `UPDATE` per table and column.
- **History by trigger or by the engine:** an `AFTER UPDATE, DELETE` trigger reads `deleted` (the before-image); `EXISTS (SELECT 1 FROM inserted)` tells update from delete. Use `SYSUTCDATETIME()` and `SUSER_SNAME()` (the login: a service account when the app shares one). A system-versioned table (`PERIOD FOR SYSTEM_TIME`, `SYSTEM_VERSIONING = ON (HISTORY_TABLE = ...)`) needs a primary key, keeps the history itself and records no user; refuse a trigger-based trail on it. History tables carry no key, default or foreign key from the source, and `nvarchar(max)` must be declared `max`, not `(0)`.
- **A column cannot be made IDENTITY in place.** Rebuild in one transaction with `SET XACT_ABORT ON`: `sp_rename` the table to `_old`, drop the foreign keys that point at it (and the child's FK to it) first, `CREATE TABLE` the new one with `IDENTITY(1,1)` and a primary key named for the new table, `SET IDENTITY_INSERT ... ON`, `INSERT ... SELECT` with an explicit column list (ids kept), `OFF`, `DROP TABLE _old`, then recreate defaults, indexes and foreign keys `WITH CHECK`. Default, FK and PK names are schema-wide, so create named defaults and FKs after the old table is dropped. Make it re-runnable by testing `COLUMNPROPERTY(OBJECT_ID('dbo.T'), 'Col', 'IsIdentity')`; afterwards check `sys.foreign_keys.is_not_trusted` is 0 everywhere. Rename a column with `sp_rename 'dbo.T.Old', 'New', 'COLUMN'` (it prints a harmless "Caution").
- **Generating `schema.sql` and `seed.sql` needs no SMO:** collect statements into `#o (ord int identity, txt nvarchar(max))` and `SELECT txt FROM #o ORDER BY ord`. Order: tables (`sys.columns` + `sys.types`, `IDENTITYPROPERTY(c.object_id,'SeedValue')`), primary keys, other indexes (`sys.index_columns`, `is_included_column`, `has_filter`), defaults, checks, foreign keys, views, procedures (`sys.sql_modules.definition`; make the first `CREATE` into `CREATE OR ALTER` with `STUFF(def, CHARINDEX(N'CREATE', def), 6, N'CREATE OR ALTER')`). Guard each object with `IF OBJECT_ID(...) IS NULL`. Leave out `sysdiagrams`, `sp_*diagram*`, `fn_diagramobjects`.
- **Dynamic SQL:** build the statement in an `nvarchar(max)` variable first (`EXEC sp_executesql N'..' + @x + N'..'` is a syntax error). The `STRING_AGG` separator must be a literal or a variable (`N',' + @nl` is rejected). An aggregate mixing an outer-query column with inner columns fails with Msg 8124 (use the inner `c.object_id` in `IDENTITYPROPERTY`). Build quoted literals with `CHAR(39)`: `'N' + CHAR(39) + REPLACE(col, CHAR(39), CHAR(39) + CHAR(39)) + CHAR(39)`.
- **A seed script that only fills empty tables** (`IF NOT EXISTS (SELECT 1 FROM T) BEGIN SET IDENTITY_INSERT T ON; INSERT ...; SET IDENTITY_INSERT T OFF; END`) is safe to run twice and never touches rows a user added. Binary columns (`image`) go out as `CONVERT(varchar(max), CONVERT(varbinary(max), col), 1)`.
- **Unique name indexes** that are not filtered (`IX_Unique_*Name`) already cover a "unique among active rows" rule more strictly but also block reusing the name of an inactive row: say so before adding a filtered index.

## Paged, searched and sorted lists through EF Core

- **A selective search plus `ORDER BY` a joined column plus `OFFSET/FETCH` can take 4 to 17 s on 100,000 rows** while each part alone takes under 100 ms: SQL Server assumes the first 10 matches come quickly (a row goal). Prove it by running the SQL EF logged with `SET STATISTICS TIME ON`, then with `OPTION (USE HINT('DISABLE_OPTIMIZER_ROWGOAL'))`. Fix with a `DbCommandInterceptor` that appends the hint to commands whose text starts with the tag from `.TagWith("DisableRowGoal")`; tag only queries that carry a search (a plain newest-first page needs the row goal). Measure before keeping it.
- **`list.Contains(x.Col)` becomes `IN (SELECT value FROM OPENJSON(@p))` in EF Core 9**, which can give that bad plan. `EF.Constant(list).Contains(x.Col)` inlines `IN (1, 2, 3)`; use it for lists of a few hundred ids. Find those ids with a small first query instead of joining the big table inside the filter.
- To see the SQL: `env "Logging__LogLevel__Microsoft.EntityFrameworkCore.Database.Command=Information" dotnet run ...` (a name with dots cannot be `export`ed in bash), then `grep -a` the log (it has binary bytes).
- A page endpoint returns the total of the filtered rows (`LongCountAsync` before `Skip/Take`), orders by the key last so pages do not repeat, whitelists sort names (400 with the valid list) and caps the page size.
