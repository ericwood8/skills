# Verify in the running app, on a scratch database copy

A passing build and unit tests do not show that the app renders. Any edit to `app.config.ts`, providers, routes or startup code needs a real run. Create, edit and delete tests write rows: never test against the real database.

## Scratch database copy

Tell the user you are making a copy (creating a database on their server is an action they should know about). The harness does it: `Docs/Verification/ScratchDatabase.ps1 -Provider SqlServer|PostgreSql|MySql -Source <db> [-User <login>] [-Drop]` (creates `<db>_scratch`; PostgreSQL and MySQL need `-User`, else psql reads `-d` as the user name and reports "Ready" with no database made: check with ``).

- **SQL Server:** backup `WITH COPY_ONLY, INIT` and restore with `MOVE` to a new name. The SQL Server **service** writes the backup, so use `SERVERPROPERTY('InstanceDefaultBackupPath')`, not a user temp folder. Get logical file names from `RESTORE FILELISTONLY`. A failing native command does not stop a PowerShell script: check `$LASTEXITCODE`.
- **Standing SQL Server test databases:** `InvoiceSystem_test` and `TimeEntry_test` already hold a copy of the real data, the routines that write (guards on) and tagged `ZZ` fixture rows (stored bad email, -5 credit, future date, rows in use, a last page of one). For SQL Server click-throughs write to those instead of making a `_scratch` copy; rebuild with `Docs/Verification/TestDatabases/Regenerate-<Name>Test.ps1` (`-SeedOnly` re-seeds). The server is in mixed mode: `akim` and `jdoe` (limited: reader, writer, EXECUTE on dbo) connect with SQL authentication, passwords through `SQLCMDPASSWORD`; a recreated user needs `GRANT EXECUTE ON SCHEMA::dbo` again. Keep a scratch copy for the full API suites, schema changes and PostgreSQL/MySQL.
- **PostgreSQL:** stop every connection to the source (a running API holds a pooled one), then `CREATE DATABASE "X_scratch" TEMPLATE "X";` (needs CREATEDB). No dump or `.bak` is left.
- **MySQL:** copy the tables (`CREATE TABLE ... LIKE` + `INSERT ... SELECT`); a login limited to one database cannot create one.
- **A throwaway Linux database:** `docker run -d --rm --name <name> -e MYSQL_ROOT_PASSWORD=<throwaway> -p 127.0.0.1:3307:3306 mysql:8.4` on a spare port (never the user's containers); wait with `mysqladmin ping`; load the schema with `docker exec -i`. Docker Desktop's engine can stop by itself, so do every check in one sitting.
- **Never pipe the script into `Select-Object -First N`:** it stops the script upstream (a SQL Server copy was left half made, backup taken and no restore). Redirect with `*> $null` and check the database afterwards. Call it from PowerShell 7 or pass SQL to `psql` on stdin: Windows PowerShell 5.1 loses the quotes around a mixed-case name, so a "Dropped" message can sit over a database that is still there. List `pg_database` / `sys.databases` after every drop.
- **MySQL login without CREATE DATABASE:** copy the procedure under another name (`ZZ_...`), call it inside `START TRANSACTION; ... ROLLBACK;` (one file per refused call, since an error ends the script), then `DROP PROCEDURE` and check `information_schema.routines`.
- **A sample's API test project** reads the scratch connection from an environment variable (`INVOICESYSTEM_TEST_CONNECTION`); run `dotnet test` there against the copy, never the real database, unless the user says so in that message.
- PostgreSQL tables live in `public`, not `dbo` (`-s public`); `codegen -t Table -T SP_Update.tt --set "Key=Value"` generates one routine against a copy; a routine can exist twice under one name (overloads): drop every `pg_proc` match before applying.
- Sanity-check row counts in both databases. Passwords go in `PGPASSWORD` / `MYSQL_PWD` / environment connection strings, never a file or parameter.
- **Afterwards:** stop the servers, drop the copy (`ALTER DATABASE ... SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE`), confirm only the real database remains, and re-check counts and one changed value in the **real** database. Remove your `.bak` from the backup folder if you can (`rm` worked there); otherwise tell the user where it is. Never enable `xp_cmdshell`.

## Run the stack

- **API:** set `ConnectionStrings__<Name>` (and any `Aspire__...__ConnectionString`) in the same command, then `dotnet run --project <Api> --no-launch-profile --urls http://localhost:5084` in the background (a `Urls` entry in `appsettings.json` otherwise wins). A first admin on an empty user table needs `Bootstrap__AdminUserName` / `Bootstrap__AdminPassword` / `Jwt__Key`. Confirm with `curl` that a GET returns rows from the copy.
- **UI:** `ng serve --port 4200` in the background; export the API address variable a proxy config reads (`services__<name>__http__0=http://localhost:5084`) first. `curl http://localhost:4200/api/<route>` returning the same JSON proves the proxy.
- **Rebuild only after stopping the API** (`MSB3027` file lock). `dotnet run` starts a child process: stop with `taskkill /PID <id> /T /F`.
- **Stop processes by listening port** (`netstat -ano | grep ":5084 .*LISTENING"` or `Get-NetTCPConnection`), printing the pid's path first. Filtering `Get-CimInstance Win32_Process` by command line also matches the shell running the command and kills it. Stop only what this session started and say which URLs are up.
- **A sample never compiled with a template hides template bugs:** build it once. Copy the sample without `bin`/`obj` to the scratchpad, drop the generated files in, build, run on a spare port (`--urls http://localhost:5091`), curl it, delete the copy. For a front-end page add a temporary route (`App.tsx` / `app.routes.ts`) after backing up the route file, run `npx tsc -b` or `npx ng build` and the page's vitest file, then revert.
- Another database, same front end: stop the other API on that port and start the new one there (React 5080, Angular 5081); the front end reads it unchanged. Say which API owns the port.

## Drive a web page in the built-in browser

- Override dialogs first (they reset on every navigation): `window.__alerts=[]; window.alert = m => window.__alerts.push(String(m)); window.confirm = () => true;`, and read `__alerts` after each action; that is how error paths (400 bad value, 400 in use) are seen.
- **Angular `ngModel`:** set `el.value = v; el.dispatchEvent(new Event('input',{bubbles:true})); el.dispatchEvent(new Event('change',{bubbles:true}))`; click with `.click()`; `await` about 1 s after each server call.
- **React controlled input:** use the native setter of the element's own prototype (`HTMLInputElement`, `HTMLTextAreaElement` or `HTMLSelectElement`; the wrong one throws "Illegal invocation"): `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el, v)`, then dispatch `input` / `change`. A text field generated as a `<textarea>` looks like an input.
- **After every write, query the database** (`sqlcmd`, `psql`) to confirm the row changed; the grid can lie (updated client-side) and an un-subscribed HTTP call changes nothing. A cleared date must be `NULL`, not an empty string.
- Screenshots time out when the window is behind others; prefer `innerText`, `get_page_text`, `getBoundingClientRect()`, `getComputedStyle`, `querySelectorAll`, `fetch`. A hidden or minimized pane cannot take clicks: drive with `javascript_tool`.
- **Set the viewport first** (`resize_window` 1280x900) and reset it with the `desktop` preset; a collapsed pane makes every element measure width 0. A closed `<dialog>` or hidden tab also measures zeros: find `dialog[open]` and check ancestors for `hidden`.
- A script that sets `location.href` is cut off: use the navigate tool, then a second script. The console buffer keeps errors from earlier loads: reload before concluding an error is current. Editing an HTML file can move the pane to the local file: navigate back to the app URL, and do the browser step after the edits. The token survives `navigate` within the app; log in through the form once.
- Use test values the server's own validation accepts; a rejected value proves the error path only, so follow it with a valid one.

## What to test per screen

Grid loads with real names and dates; the edit form pre-fills (dates, booleans, drop-downs); update, add, delete and search each reach the database; Cancel closes the form; the "in use" delete and an invalid value alert; **walk the Add path of every form, not just Edit** (a required foreign-key `<select>` starting at 0 shows the first parent in the browser but sends 0, so the database refuses it). Make the cases the screen must handle: a page with a single row (insert an 11th row so page 2 holds one, then delete it), an empty search, a reload after a sort, a stale value in `localStorage`. Read the rows, paginator text and the headers' `aria-sort` back from the DOM. Finish with `ng build` and `ng test --watch=false --browsers=ChromeHeadless` (see angular-crud-gotchas).

## Desktop (WinUI3) apps

- Drive with UI Automation from PowerShell, not screenshots: `Start-Process` the built exe (set password environment variables in the same script), wait about 6 s, find the window by process id, find controls by `NameProperty`, `InvokePattern.Invoke()` / `SelectionItemPattern.Select()`, wait about 4 s, list `Descendants` names. A loaded grid shows its row cells; an empty one only headers and "Page 1 of 1". Kill the process at the end. A first launch can show an empty grid if a previous instance is still shutting down: rerun before concluding.
- Use the exe in `bin\x64\Debug\...` (search `bin` for `*.exe`; the name may differ from the project's), not a stale `bin\Debug` one.
- ComboBox: `SelectionPattern.Current.GetSelection()` gives the selected item (the `ValuePattern` value is empty); `ExpandCollapsePattern.Expand()` then `FindAll(Descendants, ListItem)` lists options. TabItem: `SelectionItemPattern.Select()`, then list `Edit` controls by `Name`.
- Dialog traps: a TextBox commits on focus loss (`SetValue`, then `SetFocus` on the Search button, then `Invoke`); a grid far down a tall dialog has an empty `BoundingRectangle` until you `SetScrollPercent(NoScroll, 100)` its scroll ancestor (`Invoke` works off-screen, a real click does not); a header `Button`'s `Name` includes the sort arrow (`Customer PO ▼`), so match `-like "Customer PO*"`; a ContentDialog that keeps itself open can be clicked again.
- Read a cell after a formatting change (a `CurrencyFormatter` needs `IsGrouped = true` to group digits). A WinUI3 app reads `appsettings.json` from `bin`: edit that copy to point at the scratch database and put it back in `finally`.
- Add a test that parses generated XAML as XML (`XDocument.Parse`) when a template has never been built in a sample.

## Proving the check itself

- **Prove a check can fail:** after it passes, switch the fix off in the code under test (`if (false && ...)`), rebuild, run the check, look for the failure you expect, restore from a copy taken first and rebuild. Say in the notes that this was done.
- **Refactor with no behavior change:** write checks for what the script does not cover first (roles, for example), then run the same script on the old and new code: `git worktree add <scratch>/oldrepo HEAD`, build it, run with the worktree as the server repo; the old code must pass; then run the new code (same count, all pass); `git worktree remove --force` and `git worktree prune`. Check roles with real sign-ins (admin creates a manager, a report and an unrelated employee; assert 403/200 per route; capture `Location` in the script's call helper).
- **Case sensitivity:** test with two tables that differ only in case (`Movies`, `movies`) and write outputs to **distinct folders** (a Windows folder is case-insensitive, so one run overwrites the other).

## Whole-project regression check

After a template change run `codegen generate --project <sample> -o <sample folder> --dry-run --diff` over each sample's database: every file not byte-identical (line endings ignored) is listed with its diff. Expect zero differences for an unrelated change; a wanted change shows exactly where it lands. Then run the sample's `Regenerate.sh` (generate, build, tests). `.codegen-manifest.json` in the sample root tracks files: a dropped table's old files are stale; `--delete-stale` removes those you did not edit. Slow regenerate scripts go in the background with a `done` marker and a Monitor (a foreground call is cut at two minutes); do not start another build of the same project while one runs (the CLI exe and `obj` are shared).

Run them rather than rewriting the scaffolding. From Git Bash an argument starting with `/` is rewritten into a path: set `MSYS_NO_PATHCONV=1` when calling PowerShell. A scratch copy needs the right to create a database.

## Proving a template change did not move the default output

- **Byte-compare against the last commit without rebuilding or stashing:** the CLI seeds `CODEGENNEW_HOME\Templates` once from the embedded resources. Generate into folder A (current templates), then overwrite the changed `.tt` files in that seeded folder with `git show HEAD:Templates/<name>.tt` and generate into folder B with the same project; `diff -r -q A B` lists every file that moved. Run it with the new settings off for each stack touched (`--stack api --essentials`, `--stack react`) and for a project with sign-in and validation on. A difference caused by an earlier uncommitted change shows up too: read the diff before blaming the new code.
- **A scratch React app:** `npm install --no-audit --no-fund` in the generated app takes seconds; esbuild reports its postinstall as blocked, and `tsc -b`, `vitest run` and `vite` still work. Run it in the foreground (a backgrounded subshell was killed when the tool call returned). Then `npx tsc -b` and `npx vitest run` before any browser step. Vite proxies `/api` to the port in its config.
- **`form.querySelector(':invalid')` returns the `<fieldset>` around an invalid input** (a fieldset matches `:invalid` too); read `form.checkValidity()` and the input itself (`querySelectorAll('input:invalid')`) when the check names the field.
- **Test the add path with every required field of the parent**, not only the child: a blank required field elsewhere refuses the Submit, which looks like a failed save until `checkValidity()` says so.

## Look at the screen the change lives on

- A change to a form field (a caption, a mark, a drop-down) is on the **detail screen**: press Edit on a row (or Add New) and read that screen. Checking the list page, the menu or the build proves nothing about it. Do this in every stack the change touches, and compare what you read with the database (marked captions against the NOT NULL columns, `sys.columns.is_nullable`).
- **Web stacks** (React, Angular and Blazor each with its own API port): click the navigation link, click the first Edit button, then read the open `dialog` (or the Blazor `.editor`) with `javascript_tool`: captions, the span that marks them, its computed colour, and `[...inputs].filter(e => e.required)`. A read-only look at the real database is fine; save nothing. Stop what you started by port when done.
- **WinUI3**: after each click check that the process is still alive (`Get-Process <name>`). A dialog that crashes on open leaves no process and no message; look at the `Application Error` event (`Microsoft.UI.Xaml.dll`, `0xc000027b`), then log `UnhandledException` (see the winui3 skill) to get the real text. A crash may be older than your change: build the last commit in a `git worktree` and run the same script on it before deciding whose it is.
- A regenerated sample builds even when a XAML resource lookup fails at run time. Only opening the dialog finds that.
- Save a WinUI3 screenshot with `CopyFromScreen` and read the PNG; it shows what UI Automation cannot (a red colour, a header inside a ComboBox).

## Sign-in and role checks over HTTP, all stacks

- `Docs/Verification/Test-ApiSignIn.py <port> <sqlite file>` is one script for the ASP.NET, Python and Rust APIs: 55 checks (sign-in, 401 on every other route, tampered token, no hash in any answer, admin/role flags refused for an ordinary user, duplicate login, last administrator, owner scope, child through parent, throttle 429). Passwords come only from `BOSS_PASSWORD` / `WORKER_PASSWORD`, never a file.
- **A SQLite scratch database is the cheapest proof** for Python and Rust: build it with a small script (users boss manager+admin, worker, one with no password), generate with `Stacks=Python` or `Rust` and `ApiAuth=true`, `UserTable=`, `UserOwnerColumn=`, set passwords with the stack's own `set-password` (check the exit codes), start the server with `DATABASE_FILE` and `Jwt__Key` in the same command, run the script, kill the server by its listening port, delete the scratch files.
- **Prove the check can fail**: before trusting a pass, confirm the script reports failures against a server that lacks the fix or the key (generate the same project without the rule, run the same script, expect the failures).
- **A scratch SQLite project for Python, Rust, Api and Blazor** (a script file made with Write, run with a `C:/` path: Windows Python does not read `/c/...`): `--provider Sqlite -d <file>`; `EnumTables=none` (two-column tables are enums otherwise); a table with only Name and IsActive is a name/active table with no route; a table with a handful of columns and a Name looks like a lookup and gets **no search route**, so a Blazor page over it fails (give it five or more columns); `Screens=` lists the web screens; the ASP.NET API over SQLite needs `AccessMode=Ef`; a template outside the plan needs `PlanAlso=` (`TSX_Schema`). Delete the CLI's `Templates` folder before each generate, or a new template is missing.
- **Starting the servers:** Python `DATABASE_URL=sqlite:///C:/.../x.db` and `Jwt__Key`, `python -m uvicorn app.main:app --port N` from a venv (`uv venv`, `uv pip install -r requirements.txt`); the Rust binary with `DATABASE_FILE`, `PORT` and `Jwt__Key`, `set-password <login>` with `NEW_PASSWORD` in the environment for both; ASP.NET `ConnectionStrings__DbConnectionString="Data Source=C:/.../x.db"` (a `/c/...` path opens no file) with `dotnet run --no-build --no-launch-profile --urls http://localhost:N`. Scratch Rust crates can share one `CARGO_TARGET_DIR` (the dependencies compile once; a later crate takes seconds). Start each in the background, stop each by its listening port.
- **Blazor in the browser pane:** set a value with the native setter and dispatch `input` and `change` (an `InputSelect` and `InputNumber` bind on `change`), click with `.click()`, wait about a second, then read the rows back from the SQLite file with Python.
- **Real databases**: after the run, recount the real tables; set app sign-in passwords on a real database only with the generated `set-password` (password in an environment variable), then verify with an HTTP sign-in (200 right, 401 wrong).
- **uv traps (Windows)**: `uv add` needs a `pyproject.toml`; use `uv pip install`. `--system` into `C:\Python314` fails with Access denied unless run elevated: install into a venv (ask first) or run the terminal as administrator. Check what the system python really has with `python -c "import fastapi"`.
- **Rust build**: run `cargo` after `vcvars64.bat`; the first build downloads crates and takes minutes, so run it in the background with a log and a done marker.

## Proving that an update leaves a stored bad value alone

- Put a bad value in a scratch copy (`not-an-email`, a negative amount, a future date). Then four calls per layer: the stored value sent again with another column changed (accepted), the value changed to another bad one (refused), a new bad value on a different row (refused), a good value (accepted). Read the row back after each.
- Layers differ: SQL routine (call it), ASP.NET (`curl -X PUT` with the GET body edited), Python (`uvicorn` with `DB_NAME`, `ODBC_DRIVER`), Rust (`PGDATABASE`, `PORT`; `docs\cargo.cmd run`). A `400` text in FluentValidation style (`'Name' is not ...`) comes from the endpoint filter, not the attributes: a second gate to relax.
- A browser form can still stop it: `type="email"` blocks the submit natively with no request and no message in the DOM; check `window.__puts` (a fetch wrapper that records non-GET calls) before blaming the server.
- Blazor: set an input with the native setter of its prototype, dispatch `input` and `change`, click the Save button, wait about 1.5 s, read `.validation-message`. A child row's Edit opens the child page with `back=` and returns after saving.

## Traps met proving form checks in each stack

- **WinUI3:** the grid's search row has boxes named like the dialog's fields (`Billing Email Address`). Find the dialog window first and search only inside it, after selecting the tab that holds the field (`SelectionItemPattern` on the `TabItem`); a name search over the whole tree types into the filter box and the check "passes" for the wrong reason. The sample's quick regenerate build is not x64: `dotnet build -p:Platform=x64` before the click test, and point the `bin` copy of `appsettings.json` at the scratch database and put it back in `finally`.
- **Angular:** `ng serve` needs `--proxy-config proxy.conf.json` when `angular.json` has no `proxyConfig`; without it `/api/...` answers the index page with 200 and the console shows a parse error with `status: 200, ok: false`. `ng test --watch=false` (no `--browsers`) is the runner that works in the sample.
- **React:** the dev server is `npm run dev` (5173); routes are singular (`/customer?edit=5`). A tabbed form hides fields on other tabs, so read which tab is showing before and after a blocked submit.
- **Proving a relaxed check also needs the strict side:** after the unchanged-value save, change that same field to another bad value (blocked, message visible, nothing sent) and open Add with a required field empty (still blocked).
