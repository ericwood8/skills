# Sign-in and role checks over HTTP, all stacks

Read this when: you prove sign-in, roles or owner scope on the ASP.NET, Python or Rust API, or build a scratch SQLite project.

- `Docs/Verification/Test-ApiSignIn.py <port> <sqlite file>` is one script for the ASP.NET, Python and Rust APIs: 55 checks (sign-in, 401 on every other route, tampered token, no hash in any answer, admin/role flags refused for an ordinary user, duplicate login, last administrator, owner scope, child through parent, throttle 429). Passwords come only from `BOSS_PASSWORD` / `WORKER_PASSWORD`, never a file.
- **A SQLite scratch database is the cheapest proof** for Python and Rust: build it with a small script (users boss manager+admin, worker, one with no password), generate with `Stacks=Python` or `Rust` and `ApiAuth=true`, `UserTable=`, `UserOwnerColumn=`, set passwords with the stack's own `set-password` (check the exit codes), start the server with `DATABASE_FILE` and `Jwt__Key` in the same command, run the script, kill the server by its listening port, delete the scratch files.
- **Prove the check can fail**: before trusting a pass, confirm the script reports failures against a server that lacks the fix or the key (generate the same project without the rule, run the same script, expect the failures).
- **A scratch SQLite project for Python, Rust, Api and Blazor** (a script file made with Write, run with a `C:/` path: Windows Python does not read `/c/...`): `--provider Sqlite -d <file>`; `EnumTables=none` (two-column tables are enums otherwise); a table with only Name and IsActive is a name/active table with no route; a table with a handful of columns and a Name looks like a lookup and gets **no search route**, so a Blazor page over it fails (give it five or more columns); `Screens=` lists the web screens; the ASP.NET API over SQLite needs `AccessMode=Ef`; a template outside the plan needs `PlanAlso=` (`TSX_Schema`). Delete the CLI's `Templates` folder before each generate, or a new template is missing.
- **Starting the servers:** Python `DATABASE_URL=sqlite:///C:/.../x.db` and `Jwt__Key`, `python -m uvicorn app.main:app --port N` from a venv (`uv venv`, `uv pip install -r requirements.txt`); the Rust binary with `DATABASE_FILE`, `PORT` and `Jwt__Key`, `set-password <login>` with `NEW_PASSWORD` in the environment for both; ASP.NET `ConnectionStrings__DbConnectionString="Data Source=C:/.../x.db"` (a `/c/...` path opens no file) with `dotnet run --no-build --no-launch-profile --urls http://localhost:N`. Scratch Rust crates can share one `CARGO_TARGET_DIR` (the dependencies compile once; a later crate takes seconds). Start each in the background, stop each by its listening port.
- **Real databases**: after the run, recount the real tables; set app sign-in passwords on a real database only with the generated `set-password` (password in an environment variable), then verify with an HTTP sign-in (200 right, 401 wrong).
- **uv traps (Windows)**: `uv add` needs a `pyproject.toml`; use `uv pip install`. `--system` into `C:\Python314` fails with Access denied unless run elevated: install into a venv (ask first) or run the terminal as administrator. Check what the system python really has with `python -c "import fastapi"`.
- **Rust build**: run `cargo` after `vcvars64.bat`; the first build downloads crates and takes minutes, so run it in the background with a log and a done marker.
